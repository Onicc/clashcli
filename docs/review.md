# v0.1.1 整体审查

范围：命令与配置流程、下载与敏感信息、事务与回滚、系统代理、systemd、诊断日志、安装发布及测试清理。没有改变订阅原子替换模型或引入新的外部服务。

## 已修正

| 问题 | 修正与验证 |
|---|---|
| 缺少可直接使用的安装入口与 CLI 升级流程 | 本仓库 POSIX shell 脚本；架构识别、固定版本、同版本摘要、原子重命名；失败注入和真实 Linux 安装测试 |
| 下载后至 sudo 复制间文件可能变化 | 对 root 所有的目标候选再次校验，再验证程序版本；篡改回归用例 |
| `doctor` 未检查实际内核健康，却无条件要求 TUN 设备 | 验证节点/规则、监听与实际代理；TUN 关闭时设备缺失只提示；健康与故障回归用例 |
| 无响应内核的修复可能遇到仍生效的失效代理 | 修复时先在锁保护下停止服务并恢复代理，再重新启动；状态查询也为桌面检查设置超时 |
| 环境文件新增不相关变量导致代理误报，登录脚本丢失未检测 | 仅比较管理的代理变量，独立检查登录脚本；真实偏差与修复用例 |
| URL 路径/片段可携带订阅令牌，原脱敏范围不足 | 只保留 URL 主机；补充 realm 链接及格式错误 URL 测试 |
| 日志扫描停止后等待仍写日志的子进程，可能挂起 | 先终止子进程再等待；4 MiB 单行日志进程回归用例 |
| 构建工具链偏旧且缺少持续漏洞检查 | Go 1.26.8、x/sys v0.44.0；固定 govulncheck v1.8.0 加入 CI 和发布流程 |

已复核更新锁、修订号冲突、持久事务、五阶段恢复、版本保留、provider 快照、HTTP 304 依赖更新、UI 解压限制与代理卸载恢复逻辑，继续保留现有对应回归测试。审查与测试不等于形式化安全证明。

## 当前有意保留的边界

- 安装器升级 CLI，不自动替换运行中的 mihomo 或修改订阅；核心/UI 基线仍由项目固定与验证。
- 不增加第三方订阅转换、下载镜像或关闭 TLS 校验的快捷方式。
- 不自动编辑用户 shell 配置或执行 `eval`；已运行进程的环境限制保持明确。
- 独立签名/发行证明、更多架构、无 systemd 支持及可配置内核升级可作为后续版本工作，尚未宣称支持。

安装设计参考 [GitHub 发行版链接](https://docs.github.com/en/repositories/releasing-projects-on-github/linking-to-releases)、[curl 参数规范](https://curl.se/docs/manpage.html)；漏洞检查遵循 [Go 官方漏洞管理](https://go.dev/doc/security/vuln/)。具体执行结果见[验证记录](test-results.md)。
