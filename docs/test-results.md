# 验证记录

日期：2026-09-12。内核 mihomo v1.19.30，面板 MetaCubeXD v1.273.1，Go 1.25.4。测试使用真实 Linux systemd 与真实内核，不以模拟服务替代端到端验收。

## 已完成验证

| 环境 | 结果 |
|---|---|
| macOS arm64：Go race、vet、格式检查、双架构静态构建 | 通过 |
| Go 订阅解析模糊测试，30 秒，985,686 次执行 | 通过，无崩溃 |
| Ubuntu 24.04 arm64，Docker Desktop 独立网络与 cgroup | 全套通过 |
| Debian 13 arm64，Docker Desktop | 全套通过 |
| Fedora 44 arm64，Docker Desktop | 全套通过 |
| Ubuntu、Debian、Fedora amd64，GitHub 原生 Linux runner | 全套通过 |
| Arch amd64，GitHub 原生 Linux runner | 全套通过 |

功能基线 `7740c81` 的[原生 Linux CI](https://github.com/Onicc/clashcli/actions/runs/34678014100)五个任务全部成功；之后增加的真实终端用例已在本机 Linux 通过。后续提交保留同一流水线持续验证。

本机 Docker 的 amd64 容器执行返回 `exec format error`，因此没有把交叉编译当作 amd64 运行验证，也没有更改宿主虚拟机的 binfmt 配置。amd64 实际运行由原生 CI 承担。

最终本机 Ubuntu 插桩验收覆盖 `internal/app` **67.3%**、入口 **100%** 的语句。覆盖率并不代表所有故障组合均已穷尽；事务故障注入另由单元测试覆盖。

## 场景

- 初始化失败后续装、保留配置卸载后重装、完全卸载。
- 下载摘要校验、TLS 校验、私有文件权限、控制接口拒绝未认证请求。
- HTTP 代理真实流量、登录环境继承、幂等开关、原环境恢复。
- GNOME/KDE 的真实配置工具与 D-Bus；GIO 客户端实际经 GNOME 系统代理访问目标。
- TUN IPv4/IPv6 TCP、SOCKS5 UDP 转发、DNS 劫持、关闭后的设备与路由清理。
- 去掉内核网络管理能力后，TUN 更新失败并恢复旧配置及运行状态。
- SSH 面板转发在 TUN 开关期间保持可用。
- YAML、Base64、非活动订阅更新、切换、节点选择、并发更新。
- 主订阅 304 不重载；依赖单独变化时生成新版本，依赖快照可以回滚。
- 无重启热重载、坏配置/坏 provider 不替换活动版本、多次 TUN 开关不丢失上一订阅内容。
- 真正的 systemd 日历触发、内核被杀后的恢复、停止时恢复系统代理、启动时恢复保存偏好。
- 真实终端菜单与隐藏订阅输入，链接不回显。
- 单元故障注入覆盖提交前后的五个中断点、重载/检查失败、重启回退、修订号冲突、锁取消、解压路径与日志脱敏。

## 真实订阅和面板

两个用户提供的 HTTPS 订阅均通过严格 TLS 下载、候选内核预检、启用和重载。各自选择节点后，对公开的 HTTPS 204 测试端点完成了真实代理请求。URL、令牌、节点标识和原始订阅未进入仓库或公开报告；输入通过标准输入传入临时测试容器。

Chrome 人工验收确认 MetaCubeXD 页面渲染正常，使用临时密钥连接后显示两个上游版本和测试策略组；在 UI 中切换节点后，CLI 查询确认内核选择一致。已移除测试端点并关闭测试标签页，浏览器阶段在真实订阅导入之前结束。

## 修复过的验收问题

规则流式解析对单行 YAML 列表不兼容、候选 API 早于 provider 初始化、初始化失败无法续装、TUN 代次挤掉订阅历史、systemctl 等待过短、默认 timer 精度叠加随机延迟。这些问题均有对应实现修正或回归用例。

测试工具也修复了发行版 SSH 客户端依赖、登录环境差异和 tmpfs 覆盖率导出路径。曾在测试期间更新专用镜像，触发严格资源快照检查；后续停止并行改动测试镜像并重新通过清理核验。

## 清理与边界

每次验收的容器、网络和临时目录均在退出时清理，包括失败用例。最终另行删除了五个复用开发镜像、专用 BuildKit 构建器及其卷和构建缓存、本机测试二进制与本项目的模糊测试缓存；临时端口 9090 已释放。

清理后核对：原有 13 个镜像、1 个容器、1 个卷和 3 个默认网络均保留，默认构建器未改变。没有测试容器、网络或临时目录残留，Docker Desktop 恢复任务开始前的停止状态。未在 macOS 主机启用系统代理或 TUN。

额外验证 Docker 不可用时测试入口返回失败，且不会分配临时目录。发布附件的二进制架构、SHA-256 与许可证归档也已下载至内存核对，没有保存额外本机文件。

容器测试不等于完整桌面会话或所有发行版定制环境：未声称覆盖全部 KDE 应用、SELinux 强制模式、所有企业网络策略或所有公网节点。系统代理仅作用于遵循相应设置的应用；订阅原子替换不承诺已有连接绝不中断。
